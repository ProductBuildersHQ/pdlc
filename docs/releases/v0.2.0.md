# PDLC v0.2.0

*Released 2026-08-15*

This release re-exports the full six-stage PDLC model as a first-class Go API, backed by the canonical catalog entry now shipped in [`productbuildershq-frameworks`](https://github.com/ProductBuildersHQ/productbuildershq-frameworks) v0.3.0, and rewrites the lifecycle specification to match.

## What's in this release

### Six-stage model, now in code

Prior releases documented Product Definition in full but only gestured at the builder-side "Builder Lifecycle" as delegated to external methodologies. This release makes all six stages — Product Definition, Builder Definition, Implementation, Deployment, Builder Operations, Product Operations — first-class, both in the specification and in the Go module:

```go
import "github.com/ProductBuildersHQ/pdlc"

stages := pdlc.MustStages() // six stages, in canonical order

builderDef, _ := pdlc.StageByID(pdlc.StageBuilderDefinition)
```

`Stage` re-exports `productbuildershq-frameworks`' `PDLCPhase` type directly, so this module and the catalog never drift. Six stable ID constants (`StageProductDefinition` through `StageProductOperations`) let downstream consumers — [`specification-workflow-spec`](https://github.com/ProductBuildersHQ/specification-workflow-spec), [Threat Model Spec](https://github.com/grokify/threat-model-spec) — depend on `pdlc` rather than importing the catalog module directly.

### `lifecycle.md` rewritten

`docs/specification/lifecycle.md` now documents the full six-stage model: the four builder-side stages' deliverables and gates (in outline — they delegate internal process to established engineering methodologies), the ASPM security-overlay ownership boundary, and the Product Operations feedback loop that closes back to Product Definition rather than terminating the lifecycle. Product Definition's seven detailed sub-stages are unchanged from v0.1.0.

### Documentation

README.md and docs/index.md gained a Go Module Usage section covering `Stages()`/`MustStages()`/`StageByID()` alongside the pre-existing `Layout()`/`MustLayout()`, since neither had ever documented the module's Go API before this release.
